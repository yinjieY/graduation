## 摘要
针对传统农产品溯源系统“重存证、轻判险”的不足，本文围绕攸县香干质量监管场景，设计并实现了一套“区块链溯源+规则引擎+轻量AI模型”的质量安全预警系统。系统采用微服务架构，将企业认证、溯源码管理、扫码采集、风险评估、区块链存证等能力解耦为独立服务，通过网关统一鉴权与路由，实现从“扫码事件采集”到“异常识别、分级预警、联动处置、上链留痕”的全流程闭环。

在技术实现上，系统一方面基于Drools规则引擎实现可热更新的风险规则，支持监管侧动态调整阈值并快速生效；另一方面基于离线训练流程构建轻量异常检测模型，采用“教师模型训练+知识蒸馏+ONNX导出+Java本地推理”的工程化路径，提高了模型部署效率与推理可控性。围绕扫码高频场景，系统提取扫码次数、设备数、IP数、时间方差、位置方差等核心特征，结合规则分与AI分进行加权融合，输出低、中、高风险等级，并驱动系统消息、邮件/短信和二维码冻结等差异化处置动作。

实验与联调结果表明：系统已完成任务书要求的核心业务链路，能够稳定支撑二维码验真、扫码日志记录、预警记录生成、规则配置热更新与区块链存证核验。离线模型在测试集上的准确率达到0.8105，AUC达到0.9973，具备较强的风险区分能力。项目同时实现了数据脱敏、反馈取证与接口标准化封装，满足毕业设计对实用性、完整性与可扩展性的要求。本文最后总结了当前系统在公网部署、模型在线会话管理、性能压测深度等方面的改进方向，为后续工程落地与迭代优化提供参考。

## Abstract
To address the limitation of traditional agricultural traceability platforms that focus on immutable storage but lack risk judgment, this paper designs and implements an AI-enabled food safety early-warning system for Youxian dried tofu. The system integrates blockchain traceability, rule-based risk detection, and lightweight AI inference under a microservice architecture. Core services including enterprise authentication, QR trace code management, scan logging, risk evaluation, and blockchain proof are decoupled and coordinated via gateway-based routing and unified authentication, forming a full closed loop from scan event collection to anomaly detection, warning dispatch, disposal action, and on-chain evidence retention.

From an engineering perspective, the system combines two complementary channels. The first channel uses Drools for hot-updatable rule evaluation, allowing regulators to adjust thresholds dynamically with rapid effect. The second channel employs an offline AI pipeline of teacher training, knowledge distillation, ONNX export, and Java local inference for controllable and efficient deployment. Key features such as scan frequency, device diversity, IP diversity, temporal variance, and spatial variance are extracted and fused with rule scores to produce multi-level risk ratings and trigger differentiated actions including system notifications, email/SMS alerts, and QR code freeze.

Integration tests show that the platform has completed the required task-book functions and supports reliable operations for signature verification, scan reporting, warning generation, rule hot-reload, and blockchain proof verification. The offline model achieves 0.8105 accuracy and 0.9973 AUC on the test set, demonstrating strong discrimination capability. The project also implements desensitization, feedback evidence workflows, and standardized API contracts. Finally, this paper discusses limitations and future improvements in public-network deployment, ONNX session stability, and performance benchmarking.

**Key Words**: Agricultural traceability; Food safety early warning; Drools; Knowledge distillation; ONNX; Blockchain proof

## 第1章 绪论

### 1.1 研究背景
食品安全治理正在从“事后追责”向“事中预警、事前防控”转型。传统二维码溯源系统虽然能够记录“谁生产、何时生产、来自哪个批次”，但在真实监管场景下仍存在三个明显短板：一是异常行为识别能力弱，难以及时发现二维码回收复用、跨区域窜货、批量异常扫码等风险；二是溯源数据与监管动作脱节，缺少自动分级处置机制；三是系统多停留在“信息展示”层，难以形成可执行、可核验、可留痕的闭环。

结合攸县香干产业监管需求，本文在既有区块链溯源基础上建设质量安全预警子系统，强调“判险能力”与“处置能力”并重。通过将规则引擎与轻量AI模型协同，系统可对扫码事件进行实时风险判断，并联动消息通知、二维码冻结与区块链存证，从而提升监管效率与风险响应速度。

### 1.2 研究目的与意义
（1）理论意义：构建“规则+模型”双通道风险评估框架，补充农产品溯源系统在异常识别与风险融合方面的方法研究；
（2）工程意义：形成一套可复用的微服务实现路径，覆盖“数据采集-风险评估-分级预警-处置存证”闭环；
（3）应用意义：服务于中小农产品企业与地方监管部门，降低数字化预警系统建设门槛。

### 1.3 国内外研究现状
国内外研究主要集中在三个方向：
1. 区块链溯源：强调不可篡改与多方可核验，但多数系统在异常判定上能力不足；
2. 规则引擎风控：可解释性强、部署快速，但对复杂时空行为模式的泛化有限；
3. AI异常检测：对复杂模式识别能力突出，但存在模型成本、可解释性与线上部署稳定性问题。

现有研究的共性趋势是“规则引擎与模型融合”，即用规则保障可解释和边界约束，用模型提升复杂异常识别能力。本文工作与该趋势一致，并进一步结合区块链存证与监管闭环处置，强化工程可落地性。

### 1.4 研究内容与创新点
本文主要完成如下工作：
1. 设计并实现预警微服务，完成扫码监控、风险评估与预警处置全流程；
2. 基于Drools实现规则热更新，并提供监管端阈值管理接口；
3. 构建离线训练与蒸馏流程，导出ONNX模型并在Java侧接入推理；
4. 引入区块链存证机制，对关键事件进行冻结/核验留痕。

创新点体现在：
- 提出“规则分+AI分”融合计算并结合业务处置动作；
- 将模型轻量化工程流程与微服务风控链路贯通；
- 在农产品场景实现“溯源可信+预警可用+处置可核验”的一体化系统。

## 第2章 相关技术与理论基础

### 2.1 微服务与网关鉴权
系统采用Spring Cloud微服务架构，按业务域拆分为`qs-auth-service`、`qs-trace-service`、`qs-scan-service`、`qs-alert-service`、`qs-block-service`及公共模块`qs-common`。网关服务`qs-gateway-service`统一路由与JWT鉴权，前端通过`/auth`、`/trace`、`/scan`、`/alert`、`/block`前缀访问后端服务。

该架构优势在于：服务职责清晰、可独立扩展、便于故障隔离；同时通过统一鉴权和标准返回结构`R<T>`，降低前后端联调复杂度。

### 2.2 区块链存证技术
系统集成FISCO-BCOS相关接口，面向二维码创建、预警事件、冻结动作等关键业务对象生成哈希并存证。区块链层不承担复杂业务计算，而作为“可信证据层”，用于监管复核和责任追溯。该设计兼顾了链上可信与链下性能。

### 2.3 Drools规则引擎
风险规则采用Drools管理，实现阈值可配置与热更新。任务书要求的典型规则包括：
- 1小时扫码次数≥5；
- 1天设备数≥10；
- 1小时IP数≥20。

系统支持规则启停、阈值修改、手动重载接口，满足监管策略动态调整需求。

### 2.4 AI异常检测与知识蒸馏
离线训练流程以扫码行为特征为输入，构建教师模型并通过知识蒸馏训练学生模型。蒸馏后模型导出ONNX，在Java服务中通过ONNX Runtime进行本地推理。该流程兼顾效果与部署效率，适合毕业设计和中小规模生产环境。

### 2.5 安全与隐私保护
系统实现了手机号、IP等敏感信息脱敏存储；扫码反馈图片用于监管取证；二维码验签采用SM2方案并预留扩展接口，满足食品监管场景下的基础安全需求。

## 第3章 系统需求分析

### 3.1 业务需求
围绕“生产企业-消费者-监管部门”三类角色，系统需满足：
1. 企业侧：企业认证、批次管理、二维码生成与状态管理；
2. 消费者侧：扫码验真、溯源查询、异常反馈提交；
3. 监管侧：预警查看、规则配置、异常处置、存证核验。

### 3.2 功能需求
依据任务书与项目实现，核心功能包括：
- 扫码行为采集与日志留存；
- 实时风险评估（规则+AI）；
- 风险分级（低/中/高）与自动处置；
- 规则热更新与即时生效；
- 区块链存证与核验接口；
- 前后端完整联调页面。

### 3.3 非功能需求
- 时效性：异常到预警链路尽量控制在秒级；
- 性能：支撑并发访问与稳定接口响应；
- 安全性：鉴权、验签、脱敏、异常重试；
- 可维护性：接口规范化、配置中心、模块化开发。

### 3.4 用例分析（简述）
1. 企业创建批次并生成二维码；
2. 消费者扫码触发验签和扫码上报；
3. 预警服务融合规则和AI结果输出风险级别；
4. 高风险触发冻结并写入区块链存证；
5. 监管人员在后台查看并处理预警闭环。

## 第4章 系统总体设计

### 4.1 架构设计
系统采用“前端Vue + 网关 + 多后端服务 + MySQL + 区块链 + AI推理”的分层架构。数据流主链路如下：

扫码页 -> `qs-scan-service` -> `qs-alert-service` ->（通知/冻结）-> `qs-block-service`。

与之并行，企业管理链路由`qs-auth-service`与`qs-trace-service`协同完成。

### 4.2 模块划分
1. `qs-auth-service`：用户登录注册、企业认证审核；
2. `qs-trace-service`：企业/批次/二维码全生命周期管理；
3. `qs-scan-service`：扫码日志采集、反馈管理、验签前置；
4. `qs-alert-service`：规则判定、AI推理、风险融合、预警记录；
5. `qs-block-service`：链上存证与核验；
6. `qs-common`：统一响应、工具类、公共实体。

### 4.3 数据库与核心数据对象
系统采用分库或分模块数据管理思路，核心对象包括：
- `scan_log`：扫码事件明细；
- `reuse_pattern`：AI特征聚合结果；
- `alert_rule`：规则配置；
- `alert_record`：预警结果与处置状态；
- `proof_record`：链上存证索引。

### 4.4 风险融合策略设计
为平衡可解释性与泛化能力，系统将规则引擎分数与AI分数进行加权融合，形成最终风险分：

FinalScore = w1 * AiScore + w2 * RuleScore（其中w1+w2=1）

结合分段阈值映射为低/中/高风险，并与处置动作绑定。该方案简洁可控，便于监管解释与后期调参。

### 4.5 接口设计
根据项目接口清单，关键接口如下：
- `POST /scan/report`：扫码上报并触发评估；
- `POST /alert/evaluate`：风险评估与预警；
- `GET /alert/list`：预警查询；
- `PUT /alert/rules/{ruleId}/threshold`：规则阈值更新；
- `POST /block/proof/event`：事件存证。

## 第5章 系统实现

### 5.1 认证与权限实现
登录后由认证服务签发JWT，网关过滤器进行Token校验并下发到各业务服务，业务服务结合角色（ADMIN/COMPANY/CONSUMER）做接口权限控制。该机制保证监管接口、企业接口与公开扫码接口的访问边界。

### 5.2 扫码链路实现
扫码页携带`qsId`、签名载荷等参数访问公开查询接口，前端展示溯源信息后自动调用`/scan/report`上报扫码事件。扫码服务记录时间、设备指纹、IP、地理信息等，并将结果传递给预警服务。

### 5.3 风险评估实现
预警服务执行四阶段处理：
1. 特征准备：提取扫码次数、设备数、IP数、时空方差等；
2. 规则引擎：判断硬阈值命中情况并给出规则分；
3. AI模型：调用ONNX Runtime执行本地推理；
4. 融合输出：计算最终分并映射风险等级。

系统日志可输出“输入特征、规则命中、AI得分、最终得分”全过程，便于调试与答辩展示。

### 5.4 预警处置与存证实现
根据风险等级，系统执行差异化策略：
- 低风险：系统留痕；
- 中风险：发送监管通知；
- 高风险：触发冻结并调用区块链存证接口。

通过`/block/proof/verify`可核验哈希是否存在，支撑监管复核。

### 5.5 前端实现与联调
前端项目`frontend-vue`完成管理员、企业、扫码页三类入口，关键页面包括企业审核、批次管理、二维码管理、预警中心、反馈处理。根据联调清单，按钮行为均已对接真实后端API，具备完整演示能力。

## 第6章 测试与结果分析

### 6.1 功能测试
依据手工联调脚本，系统已覆盖以下链路：
1. 管理员审核企业与二维码状态管理；
2. 企业批次CRUD与二维码生成；
3. 公开扫码查询、扫码上报、反馈提交与查询；
4. 预警列表、消息列表与规则配置接口调用。

### 6.2 模型效果评估
根据离线训练输出结果：
- 数据规模：2003条，类别分布0类1403、1类600；
- 测试集准确率：0.8105；
- 精确率：1.0000；
- 召回率：0.3333；
- F1：0.5000；
- AUC：0.9973；
- 混淆矩阵：TN=287, FP=0, FN=76, TP=38。

结果显示模型对异常样本识别具有较高区分能力（AUC高），但召回率偏低，说明对部分风险样本仍存在漏检，需要后续通过样本扩充、阈值调优与代价敏感训练进一步改进。

### 6.3 任务书指标对照分析
- 规则热更新：已提供规则阈值更新与重载接口，具备快速生效基础；
- 全链路闭环：扫码->评估->预警->处置->存证流程已打通；
- 安全脱敏：手机号/IP脱敏逻辑已纳入实现；
- 模型集成：已完成ONNX导出并接入Java侧推理框架。

### 6.4 存在问题与原因分析
1. ONNX推理在部分场景出现fallback（如无会话）会影响AI分参与度；
2. 公网部署需处理`localhost`配置、CORS和Nacos环境参数；
3. 当前性能指标（QPS/P95/P99）需补充专项压测报告；
4. 推送成功率与重试结果需要形成量化统计材料。

### 6.5 优化建议
- 完善ONNX模型会话加载健康检查与降级策略；
- 引入环境变量化配置，清理硬编码本地地址；
- 增加聚合统计接口，降低前端多次查询开销；
- 开展JMeter/Gatling压测并形成图表化证据。

## 第7章 总结与展望

本文面向攸县香干质量监管场景，完成了“区块链溯源+规则引擎+AI异常检测”融合预警系统的设计与实现。项目在架构上实现了微服务解耦，在能力上实现了扫码行为实时判险，在流程上实现了预警分级与处置闭环，在可信性上实现了关键事件链上存证。通过离线训练与ONNX部署，验证了轻量AI模型在该类场景中的可行性。

从毕业设计目标看，系统已经覆盖任务书核心功能，具备可演示、可联调、可扩展特征。后续将重点从三方面推进：
1. 模型优化：提高召回率，降低漏检；
2. 工程优化：完善公网部署、配置治理与容错；
3. 评估优化：补齐高并发压测、稳定性测试和长期运行数据。

综上，本文工作证明了在地方特色农产品监管场景下，利用规则与模型协同、结合区块链可信存证，能够有效提升质量安全风险预警能力，具有较强实践价值和推广意义。
